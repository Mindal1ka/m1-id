# MOTION — система руху M1 ID (motion v2)

> Ціль: «живий» інтерфейс рівня iOS / Linear / Arc. Рух пояснює, звідки щось з'явилося і куди зникло, а не прикрашає.
> Код: `src/lib/motion/index.ts`, `src/lib/motion/motion.css`, `src/lib/motion/AnimatedNumber.svelte`.

## Жорсткі правила

1. Анімуємо **лише** `transform`, `opacity`, `filter`, `clip-path`, `translate`/`scale`. Не `width/height/top/left/margin`. Висоту — тільки через `svelte/transition` `slide` для розкриття.
2. Будь-який рух вимикається, коли `motionOK()` = false: системний `prefers-reduced-motion` або налаштування «Анімація появи» = «Вимк» (`html[data-anim="off"]`). У JS — `if (!motionOK()) return`, у CSS — `html[data-anim='off'] …` (глобальне reduced-motion вже є в `tokens.css`).
3. Тривалості: мікро 120–200ms, переходи 300–450ms, складні (шит, сторінка) до 520ms. Нічого > 700ms, крім числових «докручувань» (до 900ms) і нескінченних індикаторів.
4. Криві: `ease('spring')` / `ease('snappy')` з `$lib/motion` для WAAPI, `var(--ease-spring)` / `var(--ease-out)` у CSS, `backOut`/`cubicOut` з `svelte/easing` для transitions.
5. Hover-ефекти (tilt, spotlight, magnetic) — лише для `(hover: hover) and (pointer: fine)`; actions самі це перевіряють.
6. Не блокувати взаємодію: анімація не повинна затримувати клік/ввід. Затримка каскаду обмежена (`max` рангів), тож довгі списки не «тягнуться».
7. Нових npm-залежностей не додавати. Мова коментарів — українська.

## Продуктивність (v2)

- `html[data-perf="full"|"lite"]` — ставить `applyPerf()` на старті (`+layout.svelte`): «lite» при Save-Data, ≤4 ГБ пам'яті, ≤4 ядрах або повільному заміряному FPS; вручну — Налаштування → «Продуктивність». У JS — `fx()`.
- У «lite» лишається ВЕСЬ рух (transform/opacity); зникають blur-фільтри, backdrop-filter (скло → суцільний фон), прожектор, нахил.
- `filter: blur` — лише для одиночних елементів і лише коли `fx()`. Ніколи — для елементів списків/сіток.
- Початкова поява списків — `use:stagger`, а не `in:` з індексною затримкою на кожному елементі (див. «Двигун появи»).
- Hover-пляма `spotlight` живе в шарі `.spotlight-layer` (inset:0, overflow:hidden) — не розширює область прокрутки карток із власним скролом.

## Двигун появи (enter engine, v3)

Єдиний механізм появи карток і рядків. Глобальну CSS-появу з `nth-child` прибрано (вона рахувала лише 13 елементів — решта з'являлась разом, і билася з WAAPI).

- `autoEnter` вішається один раз у `+layout.svelte` на `body` і анімує все, що відповідає `AUTO_ENTER_SEL` (`.glass.card`, `article.glass`, `.wg-h`, `.wg-cell.filled`, `.pill`, `.m1-enter`, `[data-enter]`), крім вмісту контейнерів з `use:stagger`.
- `use:stagger={{selector, step, y, scale, blur, max}}` — свій контейнер; `max` = ранг, після якого затримка перестає рости (НЕ ліміт кількості).
- Анімується **кожен** елемент рівно один раз (WeakSet). Нові елементи, додані пізніше (дані догрузились, «Показати ще»), теж — MutationObserver.
- Порядок — за позицією: ранг = номер рядка (top) + номер колонки (left). Сітки йдуть діагональною хвилею, списки — згори вниз. Усі контейнери за кадр ранжуються **разом** (один rAF), тож сусідні секції не стартують каскад з нуля.
- Поза екраном знизу — чекають прокрутки (IntersectionObserver з запасом 15%), вище — показуються одразу. Приховані (display:none) не позначаються — з'являться один раз, коли стануть видимими. Всередині `.content` IntersectionObserver рахує відносно неї. Затримка будь-якого елемента — не більше 600 мс. Після старту сканується лише додане (MutationObserver), а не весь `body`.
- Елемент, що вже має власну скінченну анімацію (Svelte `in:`), пропускається — подвійної анімації не буває.
- Стиль появи (`html[data-anim]` = rise | fade | slide | pop) читається в момент анімації; «Вимк»/reduced-motion — лише позначає елементи. Двигун завжди підключений, тож перемикання в налаштуваннях діє без перезавантаження.
- `blur: true` — лише для одиночних невеликих блоків і лише при `fx()`. На віджетах головної вимкнено: розмиття кількох великих карток одночасно давало сильні лаги при відкритті.
- НЕ додавай власних CSS-анімацій появи на елементи, які веде двигун.
- Вхідна хореографія — один раз на реальну зміну вигляду (не на фонове оновлення тих самих даних), сумарно ≤ 500 мс.
- Довгі списки — `content-visibility: auto` + `contain-intrinsic-size`.
- Перемикання вкладок — `enterContent(contentEl, dir)` на живому DOM. View Transitions для вкладок НЕ використовуємо: знімки «замерзали» на ледачих вкладках і були дорогими.
- `backdrop-filter`: спершу `-webkit-backdrop-filter: blur(calc(Xpx + 0px));`, потім `backdrop-filter: blur(Xpx);` (guard у `vite.config.ts` рахує пари; трюк із calc не дає мініфікатору злити їх).

## Інструменти

| API | Для чого |
|---|---|
| `use:pressable={{scale}}` | Пружне натискання будь-якої клікабельної поверхні (картки, плитки, пункти). |
| `use:reveal={{delay,y,blur}}` | Поява при скролі у в'юпорт. |
| `use:stagger={{selector,step,max,y,scale,blur}}` | Каскадна поява дітей (списки, сітки, віджети) на двигуні появи: усі елементи, за позицією, поза екраном — при прокрутці, догружені — теж. |
| `autoEnter` | Глобальний двигун появи карток (один раз у `+layout`). |
| `use:smoothWheel={{ease}}` | Помірна плавна прокрутка колесом миші (на `.content` застосунку). Тачпад/сенсор, ctrl/shift+колесо і вкладені прокручувані блоки — нативно; `ease` 0.14 ≈ 300–350 мс доїзду. Тачпад визначається за дробовими/малими дельтами або deltaX (далі 400 мс нативно); зовнішня зміна `scrollTop` (`scrollTo`, клавіатура, смуга прокрутки) зупиняє анімацію. |
| `use:tilt={{max}}` | 3D-нахил за курсором (великі «геройські» картки, товари). Помірно! |
| `use:spotlight` | Світло й підсвічена рамка за курсором (картки, віджети, плитки). |
| `use:magnetic={{strength}}` | Головні CTA-кнопки. |
| `shake(el)` / `pop(el)` | Помилка / успіх. |
| `transition:springIn` / `blurFade` / `slideX={{dir}}` | Svelte transitions для поповерів, перемикання вмісту, кроків вперед/назад. |
| `enterContent(el, dir)` | Поява вмісту вкладки: `forward`/`back`/`up`/`fade`. (`withViewTransition` — застарілий no-op для сумісності.) |
| `applyPerf(mode)` / `getPerfMode()` / `fx()` | Рівень продуктивності: `auto`/`full`/`lite`. |
| `<AnimatedNumber value decimals format/>` | Числа, що докручуються (бали, монети, лічильники). |
| Класи `.lift`, `.shimmer`, `.breathe`, `.flash-update` | Підйом на hover, шимер скелетона, «дихання» live-статусу, спалах оновленого значення. |
| `animate:flip` з `svelte/animate` | Перестановки в списках (фільтри, сортування, видалення). |

## Хореографія (що де рухається)

- **Вкладки**: `enterContent` — напрям за індексом вкладки (праворуч = `forward`, ліворуч = `back`), з меню «Інше» — `up`. Навігація статична; активний індикатор у сайдбарі/нижній панелі їде пружиною (transform).
- **Вміст**: перша поява вкладки — `stagger` карток/рядків; скелетон → дані — `blurFade`; числа — `AnimatedNumber`.
- **Списки**: `animate:flip` + `in:` для нових елементів і `out:` для видалених.
- **Оверлеї**: діалог — scale 0.96→1 з пружиною + blur overlay; шит — виїзд знизу з фізикою перетягування (швидкість кидка закриває); поповер — з точки прив'язки (`transform-origin` за placement); тост — пружинний виїзд, свайп для закриття.
- **Контроли**: перемикач — пружний «великий палець» зі stretch при натисканні; чекбокс — промальовування галочки; Segmented/Tabs — індикатор, що їде пружиною; кнопки — `pressable`; помилка поля — `shake`.
- **Успіх**: здача ДЗ, покупка, замовлення — `pop` + існуючі частинки `fx.celebrate`.
